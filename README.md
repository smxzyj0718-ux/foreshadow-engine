# 伏笔引擎 (Foreshadow Engine)

给 [SillyTavern](https://github.com/SillyTavern/SillyTavern) 的长线角色扮演补上**伏笔的埋设与回收**管理。

独立 API 规划 · 增量再规划 · 受控分层注入。界面是右下角一个悬浮球 🎯，点开是完整台账面板。

> 当前版本 **0.1.1（测试版）**

---

## 它解决什么问题

长线 RP 的三个能力，对应三种完全不同的机制：

| 能力 | 本质 | 现成方案 |
|---|---|---|
| 世界设定一致性 | 检索问题 | 世界书 / 向量库 ✅ |
| 状态连续性 | 状态机问题 | 变量管理器 ✅ |
| **伏笔埋设与回收** | **规划 + 时序约束问题** | **没有** ❌ |

前两者都是**无状态查询**：你在第 300 楼问「这人是谁」，它回答。

但伏笔是一个**有状态的、必须履约的承诺**——第 20 楼埋下的东西，第 200 楼必须收，而且收的时候要让玩家回想起第 20 楼。

这需要的不是检索，是**规划器 + 台账 + 时钟**。这就是本插件。

## 安装

### 方式一：Git 网址（推荐，能一键更新）

酒馆 → **扩展** → **安装扩展程序** → 填入本仓库地址：

```
https://github.com/smxzyj0718-ux/foreshadow-engine
```

### 方式二：手动放置

把本仓库全部文件放进 `data/<你的用户名>/extensions/foreshadow-engine/`，要求该目录下有 `manifest.json`。

### ⚠️ 装完一定要刷新页面

酒馆只在**页面加载时**读取扩展。装了或更新了不刷新，页面还是旧的。

**更新出问题时，最干净的做法是删掉重装**：在「管理扩展程序」里点那一项的垃圾桶图标删除，再用仓库地址重装一次，避免旧文件残留。

### 怎么确认安装成功

右下角出现 **🎯 悬浮球**。

没出现的话，按顺序检查：
1. **管理扩展程序**里，「伏笔引擎 (Foreshadow Engine)」是否存在、**复选框是否勾选**
2. 浏览器控制台有没有 `[伏笔引擎]` 开头的报错

## 五分钟上手

初始是 **Mock 规划器**模式——**不调用任何 API**，让你先看清流程和注入效果。

1. 点 🎯 → **设置**页 → 打开 **启用伏笔引擎**
2. 回 **规划**页 → 点 **🎯 立即规划**
   - Mock 会从当前角色绑定的世界书里挑一条最像伏笔的条目（含「失踪 / 据说 / 禁忌 / 秘密」等词、含问句、尤其**从未被触发过**的条目）创建成一条伏笔
3. 去 **注入预览**页，看看到底往上下文里塞了什么
   - 注意每层底部的「**秘密层自检通过**」——秘密永远不会出现在注入里
4. 正常聊天几轮，再看**台账**页的状态变化

确认没问题后，回设置页把规划器换成真实 API。

## 规划器模式

| 模式 | 说明 |
|---|---|
| **Mock**（默认） | 内置示例，不联网。先用它跑通流程 |
| **直连自定义端点** | 浏览器直接请求 OpenAI 兼容端点。**可能被跨域拦住** |
| **直连但经酒馆后端转发** | 同上，但走酒馆自己的转发通道，绕开跨域。**推荐** |
| **使用酒馆连接配置档** | 用你在酒馆「连接配置」里存好的配置档。最安全，密钥由酒馆保管 |

### 直连模式怎么填

- **API 地址**：填到 `/v1` 为止，**不含** `/chat/completions`。例：`https://api.openai.com/v1`
- **温度**：默认 0.2。规划需要确定性，别调高
- **请求结构化输出**：勾上会带 `response_format`。部分第三方网关不支持，报错就关掉——程序有六级容错解析，纯文本 JSON 也能认

> 手机端如果报跨域错误，换「经酒馆后端转发」模式。

## 界面

悬浮球有红点数字时，表示有待裁决的冲突或履约报告。

| 标签页 | 内容 |
|---|---|
| **台账** | 活跃 / 归档伏笔，待处理项置顶。秘密层默认折叠。可手动添加、编辑、锁定、删除 |
| **规划** | 触发规划、待裁决冲突、上次结果。可查看「发送给规划器的完整内容」 |
| **注入预览** | **本轮真正会注入给叙事模型的内容**，四层分别显示，带秘密自检与 token 估算 |
| **历史** | 规划历史 + 每条伏笔的逐条变更留痕（可撤销的前提） |
| **设置** | 全部配置 |

## 四层注入

每层独立开关，可单独 A/B：

| 层 | 位置 | scan | 作用 |
|---|---|---|---|
| **L1 常驻索引** | `IN_PROMPT` | `false` | 让叙事模型「心里有数」哪些线还开着。严格控 token |
| **L2 动态调度** | `IN_CHAT` depth 4 | **`true`** | 临门一脚。最多 3 条，只写动作不写目的 |
| **契约层** | `IN_CHAT` depth 4 | **`true`** | **条件加载**——只在场景涉及「知情者在隐瞒」时才占 token |
| **落拍协议** | `IN_CHAT` depth 0 | `false` | 让叙事模型在回复末尾附一行不可见报告，零成本确认履约 |

**为什么 `scan` 要分层**：酒馆只把 `scan=true` 的注入内容送进世界书的扫描缓冲。
L2 / 契约层里点名了「管家」「阁楼」这类实体，必须 `scan=true` 才能触发对应的世界书条目，否则叙事模型只能自己瞎编这些实体是什么。而 L1 / 落拍协议措辞通用，`scan=true` 会误触发无关条目。

**depth 4 的语义**是「环境级叙事意图」——太浅会变牵线木偶，太深会被埋掉。

## 核心机制

### 1. 三方合并 —— 每次规划都在既有基础上增量改

规划器**不是**重新生成一份台账，而是输出一组**补丁**，由程序合并。四条铁律：

| 铁律 | 含义 | 破坏后果 |
|---|---|---|
| **id 永不变** | 合并锚点是 id，不是标题 | 跨楼追踪失效，同一条线被拆成多条 |
| **锁定优先** | 你标 🔒 的条目，AI 改不动任何字段 | 你的手动意图被覆盖 |
| **归档不回生** | 已回收的不能再被创建 | **同一个秘密揭晓两次** |
| **单调字段不倒退** | 已埋设楼层、已强化记录是历史事实 | 已发生的事被改写 |

### 2. 接地校验 —— 拦「模型谎报已回收」

AI 说「第 152 楼已经回收了」，**不能只凭它自己说**。
证据必须是那一楼正文里的**逐字原句**（≥8 字），否则：

- **不报错，而是降级为「候选」**，等你点确认
- **绝不自动推进状态**

为什么这么严：误判一个「已回收」会让这条线永久进归档，从此不再被调度——**不可逆的静默失败**。

### 3. 秘密层与提示层分离

每条伏笔的「真相」只给规划器看，**永远不注入给叙事模型**。
注入的是「动作」（让他藏起左手），不是「目的」（铺垫他是凶手）。

**没有这一层，插件会亲手毁掉你自己埋的悬念。**

## 常见问题

**装上了但没悬浮球？**
先看「管理扩展程序」里有没有、勾没勾上；再刷新页面；还不行就看控制台有没有 `[伏笔引擎]` 开头的报错。

**规划报跨域错误？**
换「直连但经酒馆后端转发」模式。

**结构化输出报错 / 返回空对象？**
关掉「请求结构化输出」。容错解析能吃纯文本 JSON。

**会不会污染我的世界书？**
默认**完全不写世界书**。另外采集世界书时会把 `comment` 以 `[FSP]` 开头的条目**整条剔除**，防规划器读到自己上一轮的输出。

**关掉引擎会怎样？**
所有注入被清空，对聊天完全无影响。台账保留。

## 已知限制

- **不写世界书**。镜像功能留到后续版本（需要预览 + 整书快照撤销）
- **删楼 / 倒带不会自动回滚**伏笔状态
- **不解析大纲类插件的产物**，暂未与其他插件联动
- **没有 token 预算的硬截断**，世界书按「可埋性」排序取前 N 条
- **按聊天独立存台账**（`per_chat`）；也支持按角色 / 按世界书共用

## 开发者看这里

```
manifest.json   扩展清单（酒馆只认这一个入口）
index.js        ⚠️ 构建产物，勿手改
core.js         源码：纯逻辑（三方合并 / 状态机 / 接地校验 / 调度）
app.js          源码：酒馆集成（采集 / 规划器 / 注入 / 持久化 / 事件）
ui.js           源码：界面（悬浮球 + 五页签面板）
build.mjs       构建脚本
style.css       可选样式增强（主样式内联在 ui.js，确保装上就有样子）
```

### 为什么是单文件

酒馆的 `manifest.json` **只认单个 JS 文件**，这是生态硬约束。

早期版本试过「4 个文件 + 加载器动态加载」，结果在酒馆 1.18.0 上：**扩展出现在列表里、被勾选启用，但脚本一行都不执行**（连报错都没有）。

所以改为构建成单文件——这也是成熟插件的通行做法。

### 改代码的流程

```bash
# 1. 改 core.js / app.js / ui.js
# 2. 重新构建
node build.mjs --check
# 3. 在酒馆里更新扩展 + 刷新页面
```

**永远改源码，不要改 `index.js`**（它是产物，会被覆盖）。

### 本地自测

```bash
node --check core.js && node --check app.js && node --check ui.js
```

CI（`.github/workflows/validate.yml`）会在每次推送时自动校验：语法、manifest 必填字段、`js` 指向的文件是否存在、以及**有没有把密钥提交进来**。
